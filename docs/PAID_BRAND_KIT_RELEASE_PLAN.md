# Paid Brand & AI Kit release ledger

Updated 2026-10-23. This is a prelaunch implementation map for the owner-approved quiz-led, $49 one-time offer. It is not evidence that checkout, AI synthesis, delivery or a five-minute worker is active.

## Exact source boundary

- App PR #2 (`rebuild/task-studio-20261020`, `73ed6645`) contains a working but different paid `marketing-setup-v1` contract. It remains a draft.
- App PR #3 (`rebuild/brand-kit-20261021`, `b612d881`) contains the quiz-led `brand-foundation-preview-v1`. Its campaign text is deterministic and it has no backend payment or fulfillment path. It remains a stacked draft.
- This branch adds `brand-foundation-paid-v1` model synthesis as an isolated candidate. It makes one bounded structured request, excludes private quiz answers and delivery email from the request, validates the exact CTA and selected lexical claims, and marks the result for customer review. A separate paid intake rejects edited backbriefs without new approval, incomplete quiz responses and silent text truncation. Public Markdown/JSON renderers use the saved synthesis and omit private owner preferences and the free template campaign; private owner instructions require an explicit scope choice. No application route or worker calls these modules yet. Their factual checks are not independent verification.
- Growth-agent PR #1 (`rebuild/studio-operations-20261020`, `46e5dc5d`) is a draft. Railway production was read on 2026-10-23 and is still deployed from `master` commit `f92b48d` dated 2026-03-13. The service is online with one replica, but the five-minute paid trigger is absent. Its current legacy cron variables and GitHub token remain configured. Logs showed blog cycles that skipped publication and a failed Instagram draft cycle on 2026-10-23; online status does not establish successful new-product operations.

## Remaining implementation work, in dependency order

1. **Versioned paid intake and approval:** Preserve the eight-question scoring. Add a validated `brand-foundation-paid-v1` intake that records business facts, public voice/visual choices, one offer, private owner preferences, delivery address and explicit customer approval of the backbrief. Record provenance and invalidate approval after edits. Disclose the $49 price and bounded revision scope before checkout. Do not silently accept a local preview as an approved paid brief.
2. **Commerce and schema:** Add an additive, rollbackable migration that allows the new product version and output schema without rewriting or reinterpreting `marketing-setup-v1` rows. Route Stripe metadata, line-item product name, payment-intent metadata, payment verification, fixed amount and currency through the persisted product version. Keep the original payment recovery and seven-day refund policy. No browser redirect alone can mark an order paid.
3. **Durable synthesis and output:** Dispatch by the paid order's persisted version under the existing lease and attempt limits. Apply a shared per-order model call/token/cost ceiling, record usage, save validated output before any delivery claim, and avoid consuming attempts on missing configuration. The model has no action tools. Validate campaign, source quotations, contrast, Canva summary length and export consistency, then require customer factual review. The current candidate covers one bounded call, approval-bound intake, and export rendering, but no durable dispatch or provider acceptance.
4. **Versioned delivery and private access:** Render a canonical brand guide, first email, three social posts, editable Markdown/JSON, optional private owner instructions and controlled graphics from the saved paid output. Branch the receipt, attachment, order page, download and support text by saved product version. Public exports must exclude private owner preferences by allowlist. Preserve the existing capability-fragment recovery and separate delivery ledger/idempotency key; never regenerate because an email send failed.
5. **Provider and destination acceptance:** Test a synthetic paid order end to end behind authorized hosting access: Stripe paid-state binding and webhook replay, Anthropic schema/usage, saved output, Resend acceptance and inbox arrival as distinct observations, private download, and eligible refund in the authorized provider test environment. Test ChatGPT in a new task, Canva PDF/manual transfer, and Enrich as a manual brief until a native contract is verified. Record failures and rollback before production activation.
6. **Unattended operations:** After the application release is approved and deployed, connect the reviewed growth service to the exact app endpoint with separate credentials and default-off flags. Observe two naturally scheduled five-minute `operations_runs` with final outcomes, then verify one recoverable paid test order without duplicate charge, generation or email. Record Railway deployment ID/SHA and leave old schedules or write credentials untouched until a separately reviewed migration step.

## Gates and rollback

No checkout, model-call, refund, publication, email or scheduler flag should be enabled from this branch. App production, provider configuration and Railway service remain outside this source change. A passing CI build or protected preview is not hosted customer acceptance.

Before activation, the owner must review the exact customer promise and bounded revision scope, and any new model/provider spend ceiling beyond existing approved accounts. The decision record should state the cap, how usage is measured, the stop condition and the rollback target. A failed technical gate goes back to the isolated branch for repair. Existing orders and their output format remain immutable. The rollback for this candidate is to close its stacked draft PR or revert the isolated files; for a later release, disable new checkout and worker flags first, then redeploy the known previous app/service SHAs after checking outstanding paid orders.
